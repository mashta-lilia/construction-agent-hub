# features

Кожна фіча — власна тека з обов'язковою внутрішньою структурою (CLAUDE.md, 2.1):

```
features/<name>/
├── components/     компоненти, що мають сенс лише в межах фічі
├── hooks/          локальні хуки
├── services/       виклики API та бізнес-правила саме цієї фічі
├── types/          локальні типи
├── <name>.css      ОДИН css-файл на всю фічу (+ Bootstrap-утиліти)
└── index.ts        barrel: єдина точка експорту назовні
```

Фічі MVP: `auth`, `projects`, `documents`, `reports`, `norms`, `inbox`.

Правила, які тут легко порушити випадково:

- Інші фічі та `pages/` імпортують **тільки** з `features/<name>` через
  `index.ts`. Лізти в `features/projects/components/...` з іншої фічі заборонено.
- Не плодити `.css` на кожен компонент усередині фічі — стилі йдуть в один
  `<name>.css`. Окремий css на компонент — це правило для `src/components/`,
  тобто для спільних «дурних» елементів, а не для фіч.
- Серверні дані живуть у `services/` фічі, а не дублюються в Zustand-store.
- Жодних хардкод-рядків інтерфейсу: усе через `t()` з `react-i18next`.
